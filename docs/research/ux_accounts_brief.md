# UX brief: onboarding, sign-in, connected accounts and session persistence (Q-100, D-190)

Researcher, 2026-11-11. All sources accessed 2026-11-11 (§7). Tags: **[F]** fact from the cited page, **[F-s]** fact seen only in a search-result snippet (the page was not opened), **[I]** inference, **[O]** opinion, **[U]** unverified or not found within the budget (28 of 30 web calls used).
Reading of the task (D-190): there is no app-level login. "Signup" means first-run setup. "Login/signup" also means the accounts the app creates on employer ATS sites. "Linked accounts" means a hub for Gmail, ATS tenant accounts, the Edge apply profile and Ollama.

## 1 Summary

1. Every commercial tool studied (Simplify, Teal, Huntr, Jobright, Careerflow, LoopCV, LazyApply, AIApply) needs a cloud account first. The app's data and the profile live on the vendor's server. JobScraper should **not** copy this (§6). What it should copy is how those tools import the resume first and let the owner review it [F, U1, U2, U6, U11].
2. The most useful account patterns come from local and desktop apps. Home Assistant shows each integration's health ("needs attention") and lets the user re-authenticate **in place** without deleting anything [F, L1]. Obsidian Sync uses four named states plus a filterable activity log [F, L5]. GitHub Desktop keeps its token in the OS keychain and tells the user to sign out and back in when the token is missing [F-s, L7].
3. JobScraper today: the Settings tab has Cycle, Companies per run, Appearance and Email. `MailCard` already has Check now, last-checked text, Update password and a Disconnect confirmation. `SetupChecklist` has 4 steps with an "n of m done" bar. There is no view of Workday tenant accounts, the Edge profile or Ollama health (read 2026-11-11).
4. Employer accounts differ by ATS. Workday keeps **one Candidate Home account per employer tenant**, set up per tenant and optionally email-verified [F, E2; F-s, E3]. MyGreenhouse is **one optional, password-free account** across employers that is "never created automatically" [F, E1]. The UI should therefore list Workday accounts per tenant and label Greenhouse, Lever and Ashby as "no account needed".
5. Top recommendations: a Connected accounts hub with one status card per integration, a single state vocabulary, a global "needs attention" badge, re-connect in place, an Employer accounts table, and an onboarding flow that puts the resume first and marks optional steps "Later".
6. Avoid: dependence on a cloud account, mass one-click apply, auto-submitting without a passing review, vanity completeness scores, automatic password resets and anything near a CAPTCHA.
7. Gaps: Raycast and 1Password were not researched. Huntr, Teal and Careerflow onboarding screens are known only from snippets or third parties. AIApply and LazyApply dashboards were not found.

## 3 Local and desktop app account patterns

| App | Pattern | Evidence |
|---|---|---|
| **Home Assistant** | Each integration entry is shown under Settings → Devices & services. A failing one is marked "needing attention". **Reauth keeps the entry**: the user supplies a new password or token "and everything keeps working as before". Deleting and re-adding would lose customisations [F, L1]. **Reconfigure** is a separate, user-started action [F-s, L3]. Setup failures fall into "offline" (retry automatically) and "credentials invalid" (ask the user) [F-s, L2]. Delete sits in the card's "⋯" menu [F-s community, L4] | L1–L4 |
| **Obsidian Sync** | 4 named states: Synced, Syncing, Paused (still connected), Disconnected (red). Clicking the status icon opens an activity log with timestamps, filterable by All / Errors / Skipped / Merge conflicts. The log does not survive a restart [F, L5] | L5 |
| **GitHub Desktop** | Sign in from Settings → Accounts with one button per host. Authentication happens in the browser, then the user returns to the app. The token is kept in the OS keychain. When it is missing, the documented fix is "sign out and sign back in". Logs are under Help [F-s, L7] | L7 |
| **VS Code** | An Accounts icon at the bottom of the activity bar. Each signed-in account offers "Manage Trusted Extensions" (which extensions use it) and Sign out [F-s, L8, L9]. An attention badge was not verified [U] | L8, L9 |
| **Bitwarden desktop** | **Lock** keeps local data and unlocks with a PIN or Windows Hello. **Log out** removes local data. The timeout action can be set, and "Require master password or PIN on app restart" can be switched [F-s, L6] | L6 |
| **Thunderbird** | Account wizard: name, email, password, then automatic configuration. If that fails, "Configure manually" with "Re-test" [F-s, L10, L11]. A known bug: Re-test reset OAuth2 to "Normal password" [F-s, community, L11] | L10, L11 |
| Raycast, 1Password | Not researched [U] | — |

Synthesis [I]: there are three repeated ideas. (a) **One object per connection** with a state, a reason and a single next action. (b) Recovery **in place** that keeps history. (c) A **log you can open from the status**. None of this needs a cloud account.

## 4 Employer candidate accounts

- **Workday**: each employer runs its own tenant. A tenant may require a Candidate Home account to apply. If it doesn't, Workday enables a "Candidate Verification Email". Password rules are configured per tenant under Manage External Accounts, and admins can lock accounts and reset passwords [F, E2]. One account per company, the same email accepted on many tenants, and no carry-over of login between them [F-s, secondary, E3, E4]. A newer "Workday Candidate Profile" that is reused across employers was announced; how far it has rolled out is unknown [U, E5].
- **Greenhouse (MyGreenhouse)**: one optional account for all employers on MyGreenhouse. Password-free: an email code (single-use, time-limited, a new one after 10 minutes) or Google / Apple / LinkedIn. "Accounts are never created automatically." Quick Apply fills the form from the saved profile and the candidate still reviews it. Status shows only if the employer shares it [F, E1]. Session length is not stated [U].
- **Lever, Ashby**: no candidate account was seen in earlier work (`auto_apply_brief.md`). Not re-verified here [U].
- **Implications for the UI** [I]:
  - Show an **Employer accounts** table with one row per Workday tenant host, using the F-35 DB fields (ATS, tenant, email, created, verified). Add the last sign-in result.
  - Label Greenhouse, Lever and Ashby rows "no account needed".
  - Never show MyGreenhouse as something JobScraper links: E1 says those accounts are never created automatically, and JobScraper doesn't use them.
  - Verification state matters because some tenants send a verification email (E2), which ties into F-36.

## 6 Don't copy

1. **Requiring a cloud account to use the app** (every vendor in §2) [F, U1, U11, U16]. JobScraper is local and single-user; an account adds nothing and creates a privacy surface [O].
2. **"Sign in with Google / LinkedIn" for the app itself** [F-s, U7, U16]. There is no server to sign in to. Gmail OAuth would add a consent and verification burden; whether it would need Google app verification was not checked [U]. Keep the read-only IMAP app password (F-50).
3. **Mass one-click apply** (LazyApply) [F, U14]. It brings complaints about irrelevant roles and wrong answers, and conflicts with the caps and the pre-Submit scan.
4. **Auto-submitting without a per-form check**, and **AI that adds unverified claims** (Jobright reports) [F-s, U12, U13]. These contradict D-83 and KA-4.
5. **Vanity completeness or optimisation scores** [F-s, U18]. They gamify without saying what blocks a submit. Use pattern 14 [O].
6. **Silent account creation**. MyGreenhouse makes a point of "never created automatically" [F, E1]. JobScraper creates Workday accounts only inside owner-started attempts and must list them (pattern 6).
7. **Automatic password reset after a failed sign-in**. F-35 forbids it, and resets can lock accounts that tenants manage (E2) [I].
8. **LinkedIn automation** (LoopCV, LazyApply) [F-s, U20]: a terms-of-service risk, and it is out of scope (`OVERVIEW.md`: no LinkedIn scraping).
9. **Anything that hides the automation or touches CAPTCHAs** (stealth fingerprints, solvers). This is a CLAUDE.md non-negotiable. The UI should show "Stopped: the site asks for a human check" and hand control to the owner.
10. **A test action that changes saved settings** (the Thunderbird Re-test bug) [F-s, L11].
11. **Upsells, plan-gated limits, trial nags, and open tracking on outreach email** (LoopCV) [F-s, U21]. None apply here, and open tracking is surveillance [O].
12. **Forwarding mail to a third-party address** (JobSnap) [F-s, U22]. It suits a cloud product; local IMAP is strictly more private [O].
