# ADR-0011: The local model answers every field; code keeps the mechanics and the owner's standing answers (always answer)

**Status:** Proposed (revised after the independent review `docs/reviews/Q-121-llm-first-fill-design.md`) · **Date:** 2026-11-12 · **Deciders:** owner (D-208, D-203), architect · **Design:** `../llm_first_fill_design.md` (Q-121)
**Supersedes for the default policy:** ADR-0003 §1–§3 (deterministic first, fail closed, two agreeing runs), ADR-0006's "the model chooses the source, the program checks and writes" and its lock-first order (D-82), ADR-0008 Option C ("the model reads, code decides") and the private/sensitive split for a local model (D-105, D-201). All stay in force under `apply.fill_policy: strict`.

## Context
The owner's first live attempt (Greenhouse, 43 fields) filled nothing and ended `unanswerable_required`: 28 required fields unknown although the profile and resume held the answers (the relevance guard rejected the education entry, phantom inputs since fixed by Q-119, fail-closed stops on declarations, another country's visa question, composing off, rule misses). D-208: the model reads everything, derives sensibly, must fill every field, declarations default to No, no string matching. D-203: the owner's click submits for real (`mode: auto`), with no dry-run gate. Fixed constraints: local model only, no secret in a prompt, files and identity by code, offered options only, bot-check stops, never twice, pre-Submit scan, full audit.

## Options considered
| Option | Assessment |
|---|---|
| A. Keep fail-closed; loosen guards one by one | Each new form finds the next miss: the failure class is structural (a veto per guard). Contradicts D-208. Rejected |
| B. Strict pipeline first, then an always-answer pass for what it left unknown | Two pipelines per page and doubled latency; the strict rejections still decide what the second pass must guess. Rejected |
| C. Model-first only: the model answers every field, code does mechanics and a blind last resort | One path, but the model alone decides declaration polarity, and a blind last resort ignores the profile (review H1, H2). Rejected as first drafted |
| D. Model-first, with the existing deterministic resolver as cross-check and first fallback (chosen) | The model answers every field from one cached briefing; where the tested readers are certain (declarations with their gates, work-rights rows) code writes the owner's standing answer and the model's disagreement is a note; a field the model can't answer gets the deterministic resolver first, then profile-aware family rules, marked assumed. One prompt path per field; nothing left empty |

## Decision
Option D as `apply.fill_policy: always` in the shipped config; `strict` stays selectable and is the code default (existing behaviour and pins unchanged). Hard in code: file uploads, the identity email (with its other-person guard), the owner's exact earlier answer, the standing-answer cross-check (S1), secrets refused in `backends.py`, local only (a remote backend falls back to `strict`, shown in Settings), offered options, an identity value only in a field that asks for it, coercion, read-back, bot-check stops, never twice, the pre-Submit scan. Hints only: tier-2 rows, relevance, entry scope. Removed: G2 vetoes, G4, G5 (its role on declarations moves to S1), G7, G8. A required owner-only fact (date of birth, national ID, a numeric grade, a salary) found in neither the profile nor the resume ends that role as `owner_fact_missing` ("Needs your answers", the question captured, the queue continues; a pause only when the same fact is missing 3 times in a row); `profile_incomplete` stays the general completeness gate; too many guesses on a page or attempt end as a content failure that pauses the queue without returning the role.

## Consequences
- **What the owner accepts:** under `always` with `mode: auto`, the AI's answers, including assumed and fallback answers that may be wrong, are submitted in the owner's name on real applications with no review step. The owner sees them only afterwards ("Answered for you", "What I told this employer"). This loses ADR-0003's two agreeing runs on Yes/No (S1 covers declarations and work rights only) and exposes the prompt to employer text (mitigated by a data-not-instructions rule, visible help text only and the identity-class rule).
- **Optional first-use trial:** `apply.always_trial_runs: N` (default 0, off unless the owner asks) runs the first N `always` attempts as dry runs with their assumptions shown for Keep/Change. The Coordinator puts the choice to the owner before the shipped-config line merges and records it as a D-row.
- Easier: forms whose wording differs from the profile get filled; ~3–4 calls per page; every row carries a code-verified basis or an assumed mark; the owner's corrections win next time.
- Additive contract v7 after the queue's v6 (`FillPolicy`, `Answer.assumed`, new sources, `document_missing`, `owner_fact_missing`, `QuestionStatus.ASSUMED`); schema +1 (`apply_answers.assumed`).
- Revisit if audits show wrong values with a cited fact (then code writes the cited fact), if S1 notes show frequent model disagreement (then widen S1), or if the briefing passes 18k tokens (retrieval, design §3.2).
