## Findings

### F1 MEDIUM: the model's evidence quote is stored verbatim; with the switch on it can carry the newly readable values (`apply_answers.evidence`, `fill_cache`)
Pre-existing since D-105 (the date of birth takes the same path), widened by D-201. It does not block: the store is the local DB only, so principle 6 and NF-02 (secrets) hold. It does contradict `contracts.py:966` ("decision (no private value)"), the `cache_put` docstring (`apply_flow.py:623` "never a private value") and the D-105 hook (b) "no ... cache row ... holds an S value".

- Path: `guards._model_field` -> `_grounded` rejects -> `_answer_unknown(pf, why, ungrounded=True, evidence=d.evidence)` (`guards.py:731`, also `725`, `728`, `733`, `737`, `790-796`) -> `Answer.evidence` (`guards.py:448`, up to 240 chars) -> `audit_row` `"evidence": a.evidence` (`apply_flow.py:324`). Separately, `_cache_put` stores `"evidence": d.evidence` for every cached decision (`pagefill.py:745`). That includes a rejected optional field and fact-cited decisions: only required unknowns are dropped (`pagefill.py:729-734`).
- Scenario (reproduced with dummy data on the branch): switch on, local model, profile `pay.current_salary = {amount: 4321, currency: SGD, period: monthly}`. An optional text field "Anything else we should know?" gets the model reply `{source: resume, value: "4321 SGD", evidence: "pay.current_salary | Current salary | private: 4321 SGD monthly"}`. `guards.decide` returns `BLANK_OPTIONAL`, note `G3: quote not in the source`, **evidence `pay.current_salary | Current salary | private: 4321 SGD monthly`**. The audit row stores that quote in its `evidence` column, and the fill cache stores the same quote in its decision row. The same holds for the pronouns, a sensitive `extra` answer or the account email copied from the new `private: <value>` lines. For the date of birth (D-105) the rejecting note is "G3: quote holds a private value" and the quote is stored all the same.
- Suggested fix (follow-up lane; KA-2, so spec it first): when `rctx.model_sees_sensitive` is on, store "" as the evidence of a rejected decision (`_answer_unknown`), and in `_cache_put` drop `evidence` (and `value`) of any decision whose guard answer did not fill. Or scrub the evidence with `redaction_values + s_values + protected_strings` and match the numeric leaves (`current_salary.amount`, `months_per_year`) as whole tokens only, the rule spec (g) F1 already gives. Add the `evidence` column and `fill_cache` rows to the F1 redaction pin on `tst/Q-112-pins`.

### F2 LOW: the `s_values` docstring overstates what the switch newly shows (`facts.py:941-945`)
It says that switch off, "`fact_catalogue` gives them no value, so no prompt holds them" for "names, pronouns, name order, pay, ...". With the switch off, the three `NAME_PATHS` (and `standing:full_name`) are non-private and appear in FACTS (`facts.py:50`, `126-127`; spec (a) note), and `pay.expected_salary` is in `LLM_ALLOW`. Scenario: a later reader takes the docstring as a reason to drop names from `own_details`/R4, or to assume FACTS holds no name with the switch off. Fix: "newly shown: pronouns, name order, current salary, months per year, consents, sensitive `extra` answers, the account email; the legal and preferred names only in the tier-5 prompt (FACTS always showed them)". Also qualify "switch on, prompts are redacted with nothing": `pick_option` keeps the full `s_values` (`pagefill.py:296`, `487`).

### F3 LOW (pre-existing, outside the diff): `llm_fill.py:12-13` module docstring
"Private facts are shown as "set"/"empty" only (`facts.facts_text`)". This has been false since D-105 (`llm_fill.py:363` passes `show_private`), and D-201 shows more. Spec (f)4 forbids touching `llm_fill.py` in this lane, so fix it in the next lane that touches the file.
