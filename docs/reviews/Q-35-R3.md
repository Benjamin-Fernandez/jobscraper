## VERDICT: MERGE AFTER FIXES

**Merging the branch is safe for the live app.** Nothing calls `fill_page` yet: `git grep pagefill -- src` shows only comments and docstrings outside the module. N6a/N6b wire it.

**Two HIGH findings must be fixed before the merge, or at the latest before N6a wires `fill_page`.** Both are fail-closed gaps where a value the program can't back stays on the page:
- **F1:** an optional field whose fill failed keeps the site's value. The pill fix makes this the default for a single prompt.
- **F2:** an entry delete is never verified.

F3-F6 are MEDIUM. F7-F11 are LOW.

Counts: **2 HIGH, 4 MEDIUM, 5 LOW.**

### What holds (read in the code)

**Order and no-change-before-step-9 (M9, TR-7, E7):**
- `fill_page` reads and builds facts (`check_entries` raises before any change), runs locks, cache, the chunk calls, the follow-ups and `G.decide`, then returns at step 7 on `unknown_required`. Up to there nothing on the page changes and nothing is typed.
- `services.classify(page)` runs before `_apply` (step 8). It also runs before each reveal-round `_apply`, before the added entry's fills, before the corrective pass and before the required-scan round.
- Deletes, adds and clicks come only after step 8. The module's only clicks are the entry Add and Delete (`pagefill.py:297`, `:381`) and none is a Next or Submit. There is no `press`. The widgets' Enter rule is unchanged.
- ADR-0004: `fill_page` never submits. Every failure it returns is before the click.

**Privacy:**
- Every model entry point gets `s_values=run.sv` (`facts.s_values(profile, account_email)`): `ask`, `second_opinion`, `recheck_entry` and both `pick_option` call sites.
- Both `pick_option` call sites pass `deny=enum_s_values(profile)` and `sensitive=`. The LL2 pre-decide call uses `guards.sensitive_label(pf)`. The fill-time pick uses `ans.sensitive`. `pick_refused` also checks the label and S values in the wanted text.
- `redact()` is applied inside `llm_fill` to the whole user prompt of each call. `pagefill` builds no prompt text itself.
- `inputs_hash` is built from the redacted resume. `field_sig(..., key=hash_key(rctx))` is keyed. Shown values never enter a key unhashed.
- No `log()` call exists in `pagefill`. `_Stop` and the transport notes are constants. `questions.TRANSPORT_NOTES` is matched with `startswith("transport")`, so both "transport: timed out" and "transport: model unavailable" are skipped by capture.
- The `fill_cache` row carries `source`, `ref`, `evidence`, `via`, and `value` only for resume/job/keep (LF §13.3). A fact decision stores no value.

**Cache choices (item 3), built as stated:**
- **(a) Deadline.** `_time_left` raises `_Stop(TIMED_OUT_NOTE)` before each chunk, before an LL2 pick, before step 9, and before each reveal/add/scan round's apply. `_transport` returns `transport_failed=True`, notes every undecided field "transport: timed out", and captures nothing. It is safe in itself. The gaps are in F3 and in note N1.
- **(b) No second or corrective replies.** `run.fresh` is appended only from `L.ask` (chunks), `pick` and `recheck`. `_second()` and `_corrective()` never append. `NO_CACHE_VIAS` is a second filter. Both are safe. The residual is F8.
- **A transport failure never reaches the cache.** Both `except` arms and the `run.transport` check return before `_cache_put`, and a step 7 stop returns before it too.
- **Replay goes back through locks and G1-G12.** A `facts_used_hash` mismatch is a miss and an unknown `source` is skipped. Fact values are recomputed.

**Fill-time pick (F9 from the NR review):** `_picker` runs `pick_option`, then `G.g4_ok(option, evidence or the program's words)` before the widget clicks. A failed check returns "", so the field fails. A `BackendError` sets `run.transport`, and `_transport` ends the page before the cache.

**LL2 (LF §6.4, G2(e)):** `_long_list_picks` fires only for a model answer (never a fact source) on a fully read list longer than `long_list` whose words name no option. The widget never picks; it takes an option equal to the decided value or one the injected `pick` returned (review F1 holds).

**G9 reset path:** a failed `reset_field` becomes PREFILLED, 0.5, "unverified site value", and a successful one marks the field EMPTY (`pagefill.py:315-319`).

**Re-scan (item 4):**
- After the reveal rounds (≤ 2) and the corrective pass, `_required_scan` runs `scan_required`. Hits never decided get one more round. Then `unknown` becomes `unknown_required`, else `fill_failed`.
- A seen required field that is still empty becomes `fill_failed` ("required_scan"), so the flow stops before Next.
- The whole-form scan before Submit is the flow's (N6b), not R3's (see N2).

**Layering (item 6):** `pagefill` imports only same-stage modules (`facts`, `guards`, `llm_fill`, `locks`, `page`, `widgets`, `contracts`) and `..backends.BackendError`, a foundation module and only the exception class. No SQL (the cache goes through `services.cache_*`) and no model I/O (all through `llm_fill`). `tests/test_layering.py`: 10/10.

**Ownership (item 6):** `pagefill` decides only sequencing, the LL2 trigger (a fixed LF §6.4 rule), the cache calls, G5's budget answer, and the G9 "unverified" flag for a reset it could not do. It reuses `G.UNVERIFIED_NOTE` and `G.CONF_UNVERIFIED`, and asks `G.option_for` and `G.g4_ok` for the guards' answers.

## Findings

### F1 HIGH: a failed fill on an optional field leaves the site's value on the page (G9 is never applied)
`pagefill.py:334-340` (`_apply_one` records `run.failed` and stops); `:542-552` (`_outcome` only relabels the answer FILL_FAILED); `widgets.py:356-362` (the pill fix).

- **Why:**
  - G9 says a site-origin value nobody backed is cleared, or flagged "unverified site value". LL3 and LF §11 say a search that returns nothing leaves an optional field cleared.
  - `fill_page` applies G9 only to fields the guards judged before the fill (`decision.resets`). When our fill of an optional field fails, nothing resets it.
  - Before `2d7cd45` a single prompt removed the site's pill before searching, so a miss left it empty (safe for an optional field). The fix keeps the site pill until a replacement is chosen. A miss now leaves the site value. The same holds for a dropdown, a radio or a text field whose fill ends `readback`, `site_error` or `not_decided`.
  - The flow (LF §8) blocks only on a required `fill_failed`, so an optional one goes through Next.
- **Failure scenario:**
  - An optional single-value prompt on Workday has a site default of "United States of America (+1)" (origin `site_default`). We decide "Singapore (+65)".
  - The search misses, or `pick` is refused by the deny list (the known lane M issue). The widget abandons the search and the pill stays.
  - The answer becomes FILL_FAILED. Nothing clears the pill. Next is clicked, and in `auto` mode the employer receives the US value we did not choose and could not verify.
  - The audit does say FILL_FAILED, so it isn't hidden, but the value ships.
- **Fix (in `pagefill`):**
  - After the corrective pass, for each `run.failed` key of an **optional** field whose read-back isn't empty, call `W.reset_field`.
  - If it is empty, `_mark` EMPTY and set BLANK_OPTIONAL with a note "G9: cleared after failed fill".
  - If not, set PREFILLED, `G.CONF_UNVERIFIED`, `G.UNVERIFIED_NOTE`, exactly as `_apply_one` does for a failed reset.
  - Leave required fields as `fill_failed` (the flow stops on them).
- **Tester pin:**
  - an optional single prompt with a site pill and a search miss ends cleared, or flagged unverified when it can't be reset (never silently kept);
  - the same field required ends `fill_failed`;
  - an optional radio group with a site-checked option and a failed fill ends flagged.

### F2 HIGH: an entry delete is never verified, and a failed delete leaves an untrusted entry in the application
`pagefill.py:293-299` (`_apply`), `:300-302` (fields of a deleted group are skipped for good).

- **Why:**
  - E3 (junk entry) and E6 (ungroundable optional entry) decide the delete in step 6. Step 9 clicks `delete_locator` and ignores the result (`P.click` returns "" when all four click fallbacks fail, and "direct" does not mean the entry went).
  - `run.sections` is not re-read. Every field of the group is then excluded from fills and from G9 (`run.fields[key].group in deleted`).
  - The group's answers already exist, so the reveal rounds and the required scan treat its fields as seen. Only a required empty field in it would surface, as `required_scan`.
  - The entry we judged unbacked therefore stays and ships.
- **Failure scenario (wd_a My Experience):**
  - The Workday parser imports a junk "Work Experience 3" (a heading read as a job).
  - E3 marks it for deletion, but Workday's `click_filter` overlay swallows the click, or a confirmation dialog opens.
  - Nothing is removed and nothing is detected. The entry's optional fields are skipped. The application is submitted with an entry that no resume line backs.
  - The fake page in the fixtures always honours the click, so the oracle passes.
- **Fix:**
  - After the delete loop, re-read `nav.entry_sections(page, ctx)` and compare group ids.
  - For a group still present, apply G9 to each of its fields (`reset_field`, else PREFILLED unverified).
  - If a required field of it can't be cleared, or `delete_locator` is empty, stop with those keys as `unknown` (a captured question, same as the E3 "no delete control" rule).
  - A deleted group's fields must not be skipped until its deletion is confirmed.
- **Tester pin:**
  - a delete click that does nothing (stub) → the page does not pass silently;
  - the entry's fields are cleared or the attempt stops;
  - it never ends with the junk entry intact and no flag.

### F3 MEDIUM: an expired deadline ends three different ways, and one of them captures a bogus question
`pagefill.py:267-275` (`_second`), `:361-363` (`_picker`), `:222-229` (the `recheck_entry` loop has no `_time_left`), `:132-133`.

- **Why:**
  - The accepted choice (a) is "deadline → `transport_failed`, note `transport: timed out`". `_time_left` honours it before chunks, LL2 picks and step 9.
  - `_second` returns an unknown `second` decision when `deadline_left() <= 0`. G5 then ends the field unknown, and if it is required, step 7 returns `unknown_required`. The flow captures a question for something the program could have answered if it had time.
  - The fill-time pick returns "" at the deadline, so the field becomes `fill_failed`, not a timeout.
  - `recheck_entry` is called with no deadline check, up to `max_followups` times, each up to `page_timeout_s`.
- **Failure scenario:** a Workday attempt reaches 880 of 900 s during a page's G5 second calls. The deadline passes. The page ends `unanswerable_required` and the Questions tab gets a card for a Yes/No the owner already covered. The owner answers it, the job is retried, and the same thing can happen again.
- **Fix:**
  - In `_second`, and before each `recheck_entry` call, when `deadline_left() <= 0` raise `_Stop(TIMED_OUT_NOTE)`. If `G.decide` swallows the exception (check `_second_agrees`), set a `run.timed_out` flag and have `fill_page` return `_transport(run, TIMED_OUT_NOTE)` before step 7's `unknown_required` return.
  - Do the same in `_picker` (set `run.transport = TIMED_OUT_NOTE`).
- **Tester pin:** the clock passes the deadline inside `second` → `transport_failed` with "transport: timed out" and no `unknown_required`.

### F4 MEDIUM: a required search miss ends `fill_failed` → `validation_error`, with no captured question (spec disagreement; the spec wins)
`pagefill.py:334-340`; LF §6.4 LL3 and §11.

- **Why:**
  - LF §6.4 LL3 says a search-driven list with no pickable option ends required unknown. LF §11 repeats it ("required: unknown → capture").
  - `_apply_one` records every widget failure as `fill_failed`. The flow turns a required one into `validation_error`. The owner gets no Questions card to answer, and every retry fails the same way (the cache replays the decision).
- **Known, not yours:** the two wd_a step-02 fields. Once lane M makes decide return unknown for "how heard", that one stops at step 7 correctly. The "Country Phone Code" case stays a miss until the deny-list fix.
- **Note the disagreement:** LF §8 step 11 also says "still failing → fill_failed". Both are in the spec. The two fit together if a **pick-driven miss** (`search_miss`, `no_option`) on a required field becomes `unknown_required` after step 9, which LF §8 step 10 already allows ("a required field unknown in such a round → stop").
- **Fix:** in `_required_scan`, or at the end of `_corrective`, map a required `run.failed` key whose widget note is `search_miss` or `no_option` to `unknown`. Keep `readback`, `site_error` and `not_decided` as `fill_failed`.

### F5 MEDIUM: `_add_entry` compares against stale sections after a delete, and a failed Add is silent
`pagefill.py:375-400` (380: `before` from `run.sections`; 381-382; 387-390).

- **Why:**
  - `_apply` deletes first and does not refresh `run.sections`, so `before` still lists the deleted group ids.
  - An Add that gets the same index as a just-deleted entry yields `new == []`, and `_add_entry` returns `()`. Nothing is filled and no failure is recorded.
  - If the add click fails or no group appears, it returns `()` the same way. E5 asks for the add, and the site ends without the entry and without a mark.
- **Failure scenario:** wd_a My Experience: junk #2 deleted, the source's missing entry added. The new entry becomes #2, the same id as the deleted one. The new entry is never read or filled. The scan catches only a required empty field, and even then the entry is `_seen` through the audit-key collision in F6, so it ends `required_scan` `fill_failed`.
- **Fix:**
  - Re-read `run.sections` after the delete loop, before computing `before`.
  - Record a failed Add, or an Add that produces no new group, as `run.failed` on the section's required keys, or return an `unknown` stop.

### F6 MEDIUM: `_read` hands another field's answer to a "re-created" element that is not one
`pagefill.py:164-180` (175-176); `:183-189` (`_seen`).

- **Why:**
  - A new reader key whose current audit key equals an old field's first-seen audit key is treated as that field re-created, and inherits its answer (`run.answers[key] = replace(run.answers[old], ...)`). The test does not check that the old element is gone.
  - Audit keys repeat by design (`#<entry index>` in an entry, `#n` page ordinals). A revealed field that shifts an ordinal, or a new entry reusing a deleted entry's index, collides with a live or deleted field.
  - The new field is then "seen". It is never decided, never filled, and gets G9 nowhere. The outcome carries a copied FILLED (or other) answer for a field nothing was typed into.
  - Required ones fail closed through `required_scan`. Optional ones keep their site default.
- **Failure scenario:** two ungrouped "Phone Type" fields (`#1`, `#2`). A Yes answer reveals a third between them. The new field takes `#2`, matches the old second field, and copies its answer. The audit says FILLED, the page shows nothing from us.
- **Fix:** treat it as a re-creation only when the old key is absent from the current read (`old not in {pf.field.key for pf in fields}`). Otherwise give the new key its own audit key and treat it as new.

### F7 LOW: the follow-up budget is per page, not per attempt
`pagefill.py:112-113` (`L.CallLog` is built inside each `fill_page`); `:278-279`.

LF §13.1 and `max_followups` ("≤ 25 per attempt; beyond → unknown") count across the attempt. With `CallLog` per page, a long Workday attempt gets 25 per page. The deadline still bounds time, so this is not a safety issue. Fix: pass a shared counter through `ctx` or `services`, or document it as per page.

### F8 LOW: the cache keeps a first-pass decision the site rejected, and replayed rows carry `via="cache:<via>"`
`pagefill.py:511-532`; `:423-454`; `guards.py:574` (`d.via == "recheck"`).

- **Rejected decision cached.** (b) holds, but the first-pass decision for a field the corrective pass then re-asked is still cached. A retry replays the value the site refused and pays the corrective round again. Fix: skip keys that went through `_corrective`.
- **Replayed `via`.** A replayed recheck row has `via="cache:recheck"`. Lane M's `guards._grounded` compares `d.via == "recheck"` literally, so a replayed row would take the generic copy rule (stricter, fails closed). In practice `recheck_targets` ignores `via`, so a fresh recheck replaces it and the cached recheck row saves nothing. Not unsafe. Either skip caching `recheck` rows, or ask lane M to match `via.removeprefix("cache:")`.
- **Negative pick rows.** A `pick` decision with an empty value is stored with `value=""`. If lane M later fixes the deny list, a cached "" keeps the field unknown for that job until `FILL_PROMPT_VERSION` or the model changes. Fix: do not store a pick decision whose value is empty.

### F9 LOW: two small re-scan gaps
`pagefill.py:471` (the `_apply` result in `_required_scan` is dropped); `:405-420`.

- **Dropped stop.** `_required_scan` ignores what `_apply` returns, so an added entry's unknown-required stop in that round is lost. The later scan still catches required empties.
- **Last-round fields.** After the last reveal round nothing re-reads for optional revealed fields. They get no G9 and keep any site default. Required ones are caught by the scan.

Fix: honour the return value, and optionally run one final read for G9 on fields not yet seen.

### F10 LOW: an outcome's answers are "decided", not "applied"
`pagefill.py:133`, `:555-566`.

- A step-7 stop returns `answers` with FILLED rows for fields never typed (the page is unchanged by design). `_transport` keeps FILLED answers for fields that failed to fill, and returns `fill_failed=()`.
- If N6a writes every `outcome.answers` row to `apply_answers` as-is, the audit shows values "told to the employer" that never reached the page.
- N6a should write the audit only after a page that actually filled (or mark rows on a stop as not applied). The `Path(path).read_bytes()` after an upload (`:329`) can also raise, and nothing catches it.

### F11 LOW: duplicated constants
- `L1_KEPT_NOTE` (`pagefill.py:58`) repeats the literal in `locks.py:108`. If lane M edits the note, `_apply_one` re-uploads the already-uploaded resume (safe, but a second upload). Ask lane M to export a constant from `locks`.
- `FACT_SOURCES` (`:65`) repeats the tuple in `guards.recheck_targets`.

## Notes (no action needed from R3)

- **N1, for N6a:** `fill_page` returns `transport_failed` for both the model being unavailable and the deadline. The design maps the deadline to `failed(error)` "timed out" (LF §11), the model to `failed(model_unavailable)`. N6a must check `services.deadline_left() <= 0` first and add a flow oracle. Otherwise a timeout shows as "model unavailable".
- **N2, for N6b:** the whole-form `scan_required` before Submit (LF §8 "Before Submit") and the review-text check are the flow's. `fill_page` covers only the per-page scan before Next.
- **Pill fix (item 5), summary:** it is correct for the case it fixed (a miss no longer empties a required field the flow then stops on). It does leave an unverified site value in place for an optional field. That is F1, and the same fix covers dropdowns and radios too. For single prompts the "chosen option replaces the pill" assumption is checked by the read-back (a site that adds a second pill reads back as a list and fails closed).
- **Known lane M items** (not flagged against `pagefill`): `pick_option` refuses "Singapore (+65)" because the option contains an enum S value, and `decide` returns FILLED with no fitting option for how-heard. `pagefill` handles both correctly by failing (no substitute, no guess). F4 is the only place the handling could improve.
- **Test coverage is thin.** `test_apply_pagefill` has 8 oracles, all passing. None exercises: a failed delete (F2), a failed optional fill (F1), a deadline inside `second` (F3), a cache round trip (store, replay, miss on a changed fact), the pick call arguments (`deny`, `sensitive`), or the F6 collision.
