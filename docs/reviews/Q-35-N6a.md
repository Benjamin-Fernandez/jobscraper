## Findings

### F1 MEDIUM: the `fill: llm` path can reach a real Submit without the pre-Submit scan and review check
`apply_flow.py:1146-1152` (`body_llm` tail), build plan WP-N6b, `llm_fill_design.md` §8 "Before Submit (H7)".
The design makes the H7 scan (`page.scan_required` over the whole form, then the resume-name review check) part of the path to the click; N6a deliberately leaves it to N6b (the code comment says so, and `test_apply_mail` / `test_apply_flow_llm` have one gated oracle for it). But the tail already calls `self.submit(...)` when `dry_run` is false, and `fill: llm` is the default. *Failure scenario:* the owner flips Settings -> `apply.mode` to `auto` (it is in `ApplyConfig.SETTING_KEYS`) after merging N6a and before N6b; a Greenhouse form with a required control the filler missed (or whose resume upload silently failed) is submitted with no local check, relying on the site's own validation. The owner's current mode is `dry_run`, so nothing changes today, and the D-83 gate (5 dry runs, rows read by the Coordinator) stands between now and `auto`.
Fix (3 lines, fail closed, removed by N6b): at the top of the non-dry-run tail raise `ApplyFailure(ReasonCode.ERROR, "auto submit on the llm path arrives with WP-N6b", step="review")` before `self.submit`, with the existing dry-run behaviour untouched; or have the Coordinator record "do not set `auto` before N6b merges" in the handover. Disagreement with spec: none (the spec sequences this to N6b); this is a merge-order safeguard.

### F2 MEDIUM: `backends.warm` loads the model with a different context size than the calls that follow, so the warm-up may not hide the cold load
`backends.py:225-227` (warm body: `model`, `keep_alive` only) versus `backends.py:186-187` (every call sends `options.num_ctx = self.num_ctx`), combined with the new `cli.py` line that sets `backend.num_ctx = acfg.llm_fill.num_ctx` (32768).
*Failure scenario:* warm-up loads the model at Ollama's default context; the first `fill_page` call asks for `num_ctx=32768`; Ollama restarts the runner when the context size changes, so the ~33 s cold load (D-81) is paid again inside the first page, after Edge is open, and counts against the 420 s attempt deadline; the 32k KV cache may also double the memory pressure while the old runner unloads. I did not measure this (no live Ollama in the review), so confirm with one timed dry run: the log line `model ready (N s)` should be short and the first `page <step>: ... model_seconds` should not include a load. `backends.py` is outside this diff (the warm helper predates N6a) but N6a is what makes the mismatch matter.
Fix: send `options: {"num_ctx": self.num_ctx}` in the warm body (and keep `keep_alive`), or call warm after `num_ctx` is set (it is: `cli` sets it before `run`) so the same value is used. One line plus a test in `test_backends`.

### F3 LOW: the attempt deadline starts before the warm-up
`apply_flow.py:1090-1096`: `self.context(...)` computes `ctx.deadline = monotonic() + 420` (900 for Workday), then `warm_up` runs (the Ollama backend timeout is 600 s). A slow or contended model load (the live app's discovery shares port 11434) eats the attempt budget before Edge opens; at worst the first loop check ends `error "timed out on opening"` with a browser open. Fix: set `ctx.deadline = time.monotonic() + budget` again after `warm_up` (or add the warm-up seconds back as `wait_for_mail` does). Not a safety issue.

### F4 LOW: `fileTrigger` is looser than its comment
`page.py:354-362`: the comment says "a visible button next to it (same parent) that is no other field's control", but the code accepts any visible `button`/`[role=button]` child of the input's parent. A hidden file input whose parent also holds an unrelated button (a form-level wrapper holding the Submit button, for example) is exposed as a FILE field. Consequence is bounded: an optional one is left blank; a required one stops `unanswerable_required` (fail closed); pagefill never clicks Submit. Fix: require the button to be within the same `.field`-like container as the input and not itself a submit (`c.type !== 'submit'`), or drop the parent-button clause and keep `el.labels` / `label[for]` only if the Greenhouse fixture allows.

### F5 LOW: model-unavailable detail is always "timed out on <step>"
`apply_flow.py:1174`. §11 gives the detail as "timed out on <step>" or "not running". If Ollama dies mid-attempt (connection refused rather than a timeout) the owner still reads "timed out". The staged `transport: ...` notes on the rows carry the real cause. Fix: pass the first `transport:` note into the detail. Cosmetic.

### F6 LOW: a stop after the fills leaves rows marked "not applied" that were applied
`apply_flow.py:1176-1182` / `stage(applied=False)`: pagefill steps 10 to 12 can stop (`unknown_required`) after step 9 has typed values (documented in the `pagefill.py` docstring). Those rows are written as `skipped, not applied`, which under-reports what is on the employer's page. This is the conservative direction for the audit the Coordinator reads row by row (D-83) and matches the R3 F10 suggestion ("or mark rows on a stop as not applied"); worth a sentence in the handover so nobody reads "not applied" as "never typed". Rows lost entirely: an exception inside `fill_page` (e.g. a CAPTCHA raised by `classify` after some fills) stages nothing for that page.

### F7 LOW: partial option lists for a search typeahead (accepted limit, restated)
`contracts.py:329-339`, architect's "Known limit" in §15 D-167: the reader cannot tell a partial suggestion list from a full one. A Location typeahead that shows a few default suggestions on open becomes a DROPDOWN-shaped field; a value missing from the shown list gives no fit and the attempt stops `unanswerable_required` (fails closed, never a wrong pick). Expect this to show up in the first live Greenhouse dry runs on Location (City); the e2e fixture passes with the full-list case. No change asked.
