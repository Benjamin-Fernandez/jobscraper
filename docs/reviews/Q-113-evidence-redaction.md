## Findings

### F1 MEDIUM: a rejected quote is still stored verbatim when the required scan turns its row into FILL_FAILED (pagefill.py:630 + 816, guards.py:70-72)
- **Route:**
  1. An optional field's model decision is rejected by G3 (for example, it quotes the FACTS line `profile:pay.current_salary | Current salary | private: 4321 SGD per month`). `_answer_unknown` (guards.py:745) gives BLANK_OPTIONAL, `confidence=0.0`, `value=None`, `evidence=<quote>`.
  2. At step 12, `P.scan_required` re-reads the page, and the field is now required. Conditional "required" after another answer is common on Workday ("please specify" after "Other"), or the site adds `aria-required` or an error after interaction.
  3. `_required_scan` sees BLANK_OPTIONAL, which is not UNKNOWN or UNGROUNDED, and sets `run.failed[key] = "required_scan"` (pagefill.py:630).
  4. `_outcome` rewrites the row to `status=FILL_FAILED` (816) and keeps the evidence.
  5. `quote_checked` sees non-empty evidence, a FILL_FAILED status and confidence 0.0, which is not 0.95, and returns **True**. `audit_row` stores the quote **verbatim** in `apply_answers.evidence`.
- **Not affected:** the cache row is redacted, because `_cache_put` runs at 803, before the rewrite, while the Answer is still BLANK_OPTIONAL.
- **Repro (dummy data, branch export):** `audit_row(..., dataclasses.replace(rejected, status=FILL_FAILED), ['4321 SGD per month','4321'])['evidence']` returns `profile:pay.current_salary | Current salary | private: 4321 SGD per month`, and `quote_checked` returns True. The same Answer as BLANK_OPTIONAL gives `... private: [private]`.
- **Impact:** local DB only and a narrow route, but it is exactly the leak D-202 closes, and the contract text (contracts.py:966) stays false on this path. It is not blocking (MEDIUM).
- **Fix (storage only, one line in `quote_checked`):** also require that the field took a value, e.g. `and a.confidence > 0 and a.value not in (None, "", [], ())`. Every `_answer_unknown` row has `value=None` and `confidence=0.0`. Every checked row has both set, including FILL_FAILED of a checked FILLED row (816 and apply_flow 1515 keep value and confidence) and the `_clear_failed_optional` PREFILLED row at 0.5. Then:
  - correct the `quote_checked` docstring and spec §2 ("only 747/804"; the branch lines are 761 and 818);
  - add a pin to `tst/Q-113-pins`: a rejected optional with a quote, then FILL_FAILED, gives redacted evidence.

### F2 LOW: a checked quote whose field ended without a value is cached redacted, and replay then fails at G3 instead of re-asking (pagefill.py:760, spec §5)
- **Scenario:**
  1. An optional yes/no field quotes the resume line "Languages: English, Chinese". G3 passes, then G5 disagrees and the field becomes BLANK_OPTIONAL with no evidence on the Answer (guards.py:755-758).
  2. The cache stores "Languages: English, [private]", because "chinese" is an `enum_s_values` word when the owner's race is Chinese.
  3. On replay G3 rejects it ("quote not in the source").
  4. Before D-202, replay passed G3 and asked the second opinion again, which could now agree and fill.
- The same applies to G4 and G11 rejections, which only change the note, and to the rare `_clear_failed_optional` case with no corrective re-read (the key is not in `run.corrected`).
- **Impact:** the result is fail-closed and optional-only. Spec §5 says "only the note can change"; strictly, a later G5 agreement is lost. **Accept**, and record the note in spec §5. No code change.

### F3 LOW: the value set matches whole values only; partial or reformatted copies of a private value stay
- **Scenario (switch on):** a rejected quote copies part of a multi-word private value ("dyslexia" out of the sensitive `extra` "mild dyslexia", or a street fragment) or reformats the salary ("4,321" or "S$4.3k" for 4321). `redact` leaves it unchanged.
- An unvalidated string amount "4,321" gives the digit run "321", so the quote "4,321" is stored as "4,[private]".
- The spec defines the set as the existing whole values (§3), so this is a residue and not a departure.
- **Suggested follow-up (optional):** for private `text`, `salary` and `number` facts, also add the comma-grouped form of each amount, e.g. `f"{int(x):,}"`. Note the partial-text residue in spec §3.
