## 2. Fake model (`tests/llm_fill_support.py`, T1)

- `FakeFillBackend(replies, strict=True).complete(system, user, max_tokens, schema=None, timeout=None, *, format=None, temperature=None, seed=None, keep_alive=None, **kw)` records `(kind, system, user, format, kwargs, prompt_hash)` per call.
- **Kind:** system-prompt constant (page / pick / recheck); `temperature == 0.7` → second; a field view with `site_error` → corrective; `RESUME ENTRY` → `entry:<group>`.
- **Keys:** the fake parses `FIELDS (JSON):` into `{id: (group, norm(question))}`; replies are keyed `"<group>|<question>"` and written back with the prompt's ids. This survives random reader ids and call order. The prompt hash is recorded only, never a key (it changes with the sample profile).
- **Reply file:** `{"calls":[{"kind":"page","reply":{"|First Name":{"source":"profile","ref":"profile:identity.legal_first_name","value":"","evidence":""}}}, {"kind":"page","raise":"BackendError"|"done_reason":"length"|"text":"{bad"}]}`. Strict: an unmatched call raises `AssertionError` naming its questions.
- `assert_no_secrets(deny)` runs over every recorded `system + user + format` at the end of each T2/T4 test.

## 3. Fixtures and sanitising (T1)

`tests/fixtures/apply/llm_fill/` holds:
- `README.txt` (steps + scan command);
- `shim.js`, test-owned, because static recordings hold no pop-ups. It emulates the Workday listbox, prompt (categories, search, pills), dates, upload name, Delete/Add, Next and `inputAlert`;
- `wd_a/NN-<step>/{page.html,fields.json,reply.json}` × 7 and `wd_b/02-my_information/` (required "Additional Address");
- `stubs/{prompt_categories,listbox_error,dates,honeypot,file_slots}.html`;
- `replies/<case>.json`;
- `resume_sample.txt`, whose header carries the sample contact values so the privacy oracle bites, and `jd_sample.txt`.

**Procedure** (the recordings stay in the session scratchpad):
1. Read only `NN-*.html` and `fields_*.json`. Never open `profiles/` (live browser sessions), `*.png`, `prompt_*.json`, `answers.json`, `account.json`, `state.json`, `tenants.json` or `notes.md`.
2. Strip: keep the `applyFlowPage` scope. Remove `<script>`, `<link>`, `<iframe>`, images and `srcset`, remote `url()`, `on*`, `nonce` and the spike's `data-llmfill` marks. Replace `<style>` with a small local CSS. Keep `data-automation-id`, `aria-*`, `role`, `id` and `for`.
3. Synthetic values: inputs, textareas, pills, listbox texts and file names get the sample profile's values (mapped by label via `fields_*.json`). Imported entries become the sample entries, plus one junk entry (E3) and one description with a Projects block appended (E4).
4. Identifiers: employer and aliases → "Example Employer"; posting title → "Example Role"; tenant host → `example.wd1.myworkdayjobs.test`; requisition ids → `REQ-0000`. Labels and options stay verbatim (form vocabulary).
5. Scan (a), every run: no e-mail outside `example.(com|org)`; no `(\+65)?\s?[689]\d{3}\s?\d{4}`, `[STFGM]\d{7}[A-Z]`, `myworkdayjobs\.com`, `\bwd\d+\.` or `\b(R|JR)-?\d{5,}`; no `*.png`.
6. Scan (b), when `JOBSCRAPER_FIXTURE_DENYLIST` names a file outside the repo (the Coordinator builds it from the owner's profile, resume, account email, employer names and hosts): every entry absent, case-insensitive, digits-only variants too. Commit only after (a) and (b) both ran clean.
7. `fields.json` is hand-written by the tester from the spike's field structure, never generated by lane R's reader (no circular oracle).

## 5. Locks, privacy, model call (T2)

- **Lock precedence** (`locks`). For L1–L6 the fake also replies for the locked id; the lock's answer still stands, the schema has no property for that id, and the prompt shows `locked: true` with no value when private.
  - L1: another file name is replaced; "Transcript" gets `documents.transcript`; a required "Cover letter" → UNKNOWN, not captured (TR-8).
  - L3: AMBIGUOUS → `attestation_unclear`, 0 model calls.
  - L4: conflict → `conflict`.
  - L7: "…confirm you have no criminal record?" → `attestation_unclear`; "non-compete" → normal L3.
- **S values never in a prompt.** Deny-list = every S-path value of the sample (phone with and without the country code, email, DOB in ISO and D/M/Y, NRIC last 4, address, postal) + the account email. It is checked over every call, including the resume header and imported `current` values (that part waits on TR-1). With `debug_dump` off nothing is written; no log line holds an S value or prompt text.
- **Model call** (`model`):
  - block order FACTS → RESUME (or RESUME ENTRY) → JOB → PAGE → FIELDS; FACTS identical across an attempt (TR-11);
  - `ref` enum = catalogue + `""`; value enums by kind; `max_tokens = 120·n + 200 ≤ 8000`; temperature 0, seed 7;
  - one chunk per entry, ≤ 20 per other chunk; FILE fields never sent; private facts `(private, set|empty)`;
  - `length` → split once; bad JSON → retried once; `BackendError` → `transport:` notes.
- **Facts** (`facts`): template rows dropped; `nationality` private; `standing:today` from an injected UTC instant (`2026-11-02T16:30Z` → `2026-11-03`, TR-5); E2 exact / junk / tie.

## 6. Stop, capture, flow, replay smoke (T4, T5)

- **Stop** (`apply_flow_llm`): `wd_b` → `failed(unanswerable_required)`, detail = the first label, after one `CapturedQuestion` (`profile_gap`, `target_path`, verbatim label). No fill or clear after the stop (TR-7). Transport unknowns are never captured.
- **`model_unavailable`:** the warm-up fails before `browser_factory` is called (count 0); a page call timeout gives "timed out on <step>".
- **Flow:** the same step twice, or no fields on a non-review step → `page_unrecognised`; review without the resume's file name → `validation_error`; caps and duplicate oracles stay green. The Workday navigator runs on `127.0.0.1` through a REGISTRY test subclass.
- **Cache** (`store_fill_cache`): round-trip, purge, migration on a copy, locks never cached; a retry after an answer → 0 calls (waits on TR-2).
- **Replay smoke** (`test_replay_wd_a_dry_run_reaches_ready_to_submit`, needle `apply_flow_llm`): the 7 `wd_a` steps over `http.server` + `shim.js`, with the real reader, widgets, pagefill, guards and flow and the fake model. Expected: `ready_to_submit`; one audit row per field per step with the 4 new columns; `data-submit-count=0`; all prompts pass `assert_no_secrets`.
- **T5:** LF §12 (the F1 reuse matrix; an F3 cleared variant sends `[]`; F4 "ARE YOU AUTHORIZED TO WORK IN THE US?" → conflict or Yes) and the `capture_page` F1 cases.

## 7. Live dry run only

Model accuracy and prompt rules 5–7; latency (NF-07), prefix reuse (`prompt_eval_ns`, WP-M4), warm-up; real Workday widget timing, `click_filter` overlays, uploads, the parser's output; the account wall, CAPTCHA, confirmation after a real Submit; MyGreenhouse selectors (S-6).
